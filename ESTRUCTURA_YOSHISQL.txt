                                   YoshiSQL
              Entorno gráfico de escritorio para SQL Server en Linux
                         C# + .NET 10 + Avalonia UI (MVVM)

--------------------------------------------------------------------------------
1. ARQUITECTURA EN CAPAS
--------------------------------------------------------------------------------

    ┌──────────────────────────────────────────────────────────┐
    │  YoshiSQL.Escritorio      (Interfaz gráfica - Avalonia)  │
    └────────────────────────────┬─────────────────────────────┘
                                 │ usa
    ┌────────────────────────────▼─────────────────────────────┐
    │  YoshiSQL.Aplicacion      (Casos de uso / servicios)     │
    └────────────────────────────┬─────────────────────────────┘
                                 │ usa
    ┌────────────────────────────▼─────────────────────────────┐
    │  YoshiSQL.Dominio         (Entidades y contratos)        │
    └────────────────────────────▲─────────────────────────────┘
                                 │ implementa
    ┌────────────────────────────┴─────────────────────────────┐
    │  YoshiSQL.Infraestructura (SQL Server, disco, seguridad) │
    └──────────────────────────────────────────────────────────┘

    Regla de oro: las dependencias siempre apuntan hacia el Dominio.
    - Dominio:          no depende de NADA (ni de SQL Server, ni de Avalonia).
    - Aplicacion:       solo conoce al Dominio (trabaja con interfaces).
    - Infraestructura:  implementa las interfaces del Dominio.
    - Escritorio:       muestra datos y llama a la Aplicacion; nunca escribe SQL.

    Así, si mañana se agrega PostgreSQL, solo se crea una carpeta nueva en
    Infraestructura (ej. Infraestructura/PostgreSql/) sin tocar lo demás.

3. CONVENCIONES DE CÓDIGO LIMPIO
--------------------------------------------------------------------------------

3.1 Idioma y caracteres
    - Todo el código en español: clases, métodos, variables, comentarios.
    - SIN tildes ni ñ en nombres de código, para evitar problemas de codificación:
          Pestaña  -> Pestana        Diseño   -> Diseno
          Función  -> Funcion        Año      -> Anio
      (En textos visibles para el usuario sí se usan tildes y ñ.)
    - Se conservan los términos estándar de .NET que no conviene traducir:
          sufijo Async, prefijo I en interfaces, palabras clave de C#.

3.2 Formato de nombres
    Elemento                  Formato            Ejemplo
    ------------------------  -----------------  ------------------------------
    Clase / Record            PascalCase         ServicioDeEjecucion
    Interfaz                  I + PascalCase     IEjecutorDeConsultas
    Método                    PascalCase(verbo)  ObtenerTablasAsync
    Propiedad                 PascalCase         NombreDelServidor
    Variable local            camelCase          filasAfectadas
    Parámetro                 camelCase          perfilDeConexion
    Campo privado             _camelCase         _ejecutorDeConsultas
    Constante                 PascalCase         TiempoMaximoDeEsperaEnSegundos
    Enum y sus valores        PascalCase         EstadoDeEjecucion.Cancelada
    Archivo                   = nombre de clase  ServicioDeEjecucion.cs

3.3 Reglas de nombres
    - Métodos: siempre empiezan con un VERBO en infinitivo.
          Bien:  ObtenerBasesDeDatosAsync()     Mal:  BasesDeDatos()
          Bien:  EjecutarSeleccionAsync()       Mal:  Ejec()
          Bien:  CancelarEjecucion()            Mal:  Stop()
    - Booleanos: preguntas que se responden con sí o no (Es, Esta, Tiene, Puede).
          EstaConectado, TieneCambiosSinGuardar, PuedeEjecutar, EsLlavePrimaria
    - Colecciones: en plural.
          tablas, columnasSeleccionadas, mensajesDeError
    - Sin abreviaturas ni nombres genéricos.
          Mal:  cnx, tbl, res, dato, temp, aux, obj, x
          Bien: conexion, tabla, resultado, columnaActual
    - Métodos asíncronos terminan en Async y reciben CancellationToken.
          Task<ResultadoDeEjecucion> EjecutarScriptAsync(
              string textoSql, CancellationToken tokenDeCancelacion);

3.4 Reglas de diseño
    - Una clase por archivo; el archivo se llama igual que la clase.
    - Cada clase tiene UNA responsabilidad (ej. el divisor solo divide por GO).
    - Métodos cortos: si un método no cabe en pantalla, se divide.
    - Máximo 3 o 4 parámetros; si son más, se agrupan en un objeto.
    - Nada de "números mágicos": se usan constantes con nombre.
    - Las dependencias se reciben por el constructor (inyección de dependencias),
      nunca se crean con "new" dentro de los servicios.
    - Las vistas (.axaml) no contienen lógica; esa vive en el ModeloDeVista.
    - El SQL de catálogo vive en archivos .sql, no en cadenas dentro del C#.
    - Los comentarios explican el POR QUÉ, no el QUÉ (el nombre ya dice el qué).
    - Nunca se guardan contraseñas en texto plano.

3.5 Ejemplo de estilo esperado

    public sealed class ServicioDeEjecucion
    {
        private readonly IDivisorDeLotes _divisorDeLotes;
        private readonly IEjecutorDeConsultas _ejecutorDeConsultas;

        public ServicioDeEjecucion(
            IDivisorDeLotes divisorDeLotes,
            IEjecutorDeConsultas ejecutorDeConsultas)
        {
            _divisorDeLotes = divisorDeLotes;
            _ejecutorDeConsultas = ejecutorDeConsultas;
        }

        public async Task<ResultadoDeEjecucion> EjecutarAsync(
            string textoSeleccionado,
            CancellationToken tokenDeCancelacion)
        {
            var lotes = _divisorDeLotes.DividirPorGo(textoSeleccionado);
            return await _ejecutorDeConsultas.EjecutarLotesAsync(lotes, tokenDeCancelacion);
        }
    }

4. FLUJO DE EJEMPLO: EL USUARIO SUBRAYA CÓDIGO Y PRESIONA F5
--------------------------------------------------------------------------------

    1. PestanaDeConsulta.axaml           Detecta F5 y el texto subrayado
    2. PestanaDeConsultaModeloDeVista    Si hay selección la usa; si no, todo el texto
    3. ServicioDeEjecucion               Pide dividir el texto por GO
    4. DivisorDeLotesTSql                Devuelve la lista de LoteSql
    5. EjecutorDeConsultasSqlServer      Ejecuta cada lote en segundo plano
    6. ResultadoDeEjecucion              Vuelve con resultados, mensajes y tiempo
    7. ResultadosModeloDeVista           Llena la grilla y la pestaña de mensajes
    8. BarraDeEstado                     Muestra "Completada | 120 filas | 00:00:01"
